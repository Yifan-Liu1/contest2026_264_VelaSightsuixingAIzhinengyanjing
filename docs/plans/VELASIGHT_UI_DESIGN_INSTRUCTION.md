# VelaSight UI Design Instruction

> 文档状态：2026-08-20 三层统一布局稿，依据 2026-08-18《OpenVela 竞赛功能梳理和流程拆解》会议记录、当前 VelaSight 源码和实板反馈制定。
> 本文冻结设备端显示和按键交互，不冻结云端 URL、JSON 字段和模型端点；协议细节以云端接口文档为准。

## 1. 设计目标

VelaSight 是一个三键、双圆屏、弱交互 AI 接入终端，不是小型手机。用户只负责选择、开始、暂停、结束和确认，设备负责采集、分析、提醒、总结和播报。

交互必须满足：

- 信息少而明确，重要内容大字号显示。
- 双屏统一使用上、中、下三层结构，两条分界线在相同纵坐标上，页面切换不得改变分层高度。
- 上层只显示单行、四个或更少的汉字；较长含义必须改写为四字短标题，不能换行、缩小或滚动。
- 用户始终知道当前状态、下一步动作和对应按键。
- 短按显示按键响应，长按隐藏软键名称并专注显示进度。
- 两个屏幕职责不重复：物理左屏 `/dev/fb1` 显示内容，物理右屏 `/dev/fb0` 显示索引、状态和动画。
- 普通社交过程保持安静，只在检测到强烈情绪变化时提示。
- 历史记录中始终保留一张空白页，提供单张照片多模态 AI 交互入口。
- 不在错误界面提供“长按失败返回”或其他长按失败路径。
- 产品构建取消原有板级开机问候动画；面板初始化期间保持背光关闭，双 framebuffer 注册后先提交纯黑保护帧，再启动隐藏状态下的 VelaSight。LVGL 同步完成双屏首帧后才开启背光，首个可见业务画面由 LVGL 完整接管。

## 2. 会议功能基线

### 2.1 社交辅助模式

社交辅助模式由用户明确开始和结束一次会话：

1. 历史页长按确认键进入社交辅助，长按期间显示进入进度。
2. 会话中持续采集图像和音频。
3. 图像用于表情识别；音频按约 2 秒分块上传，由云端拼接并转字幕。
4. 图像按设备可信能力逐张上传，首版以约 3 FPS 为演示基线，5 FPS 仅作为挑战目标。
5. 云端发现强烈情绪变化时，先返回即时情绪变化、颜色和短文本；设备中途不播放 TTS。
6. 用户长按返回键结束会话，云端基于字幕、情绪、置信度和时间戳生成最终摘要、建议和结构化记录。
7. 结果返回设备后，以文本显示和最终 TTS 为主要输出，并保存处理后的历史记录，不保存原始音视频。

### 2.2 闲时语音助手

闲时语音助手不经过团队自建社交会话云，由设备侧 `ai_agent` 直接编排模型 API：

- 在历史记录页选中一条记录后，短按确认键，对当前记录进行语音问答。
- 设备录音，VAD 自动判断结束；确认键短按也可以手动结束录音，返回键短按可以取消。
- 设备获得回答后，屏幕显示一至两行摘要，TTS 播报完整回答。
- 闲时助手只携带当前选中的一条记录，不带历史目录、其他会话或隐式长期上下文。

### 2.3 空白页多模态 AI 交互

历史索引最后固定保留一张“空白页”，它不是一条历史记录，也不参与历史数量统计。

空白页用于没有选中历史记录，或用户希望针对眼前事物直接提问的场景：

1. 用户在历史记录页按“下一条”循环浏览，记录之后进入空白页。
2. 左屏明确提示“拍照提问”。
3. 用户短按确认键后，设备只拍摄一张可信 JPEG。
4. 用户随后说出问题，或按确认键结束录音。
5. 单张照片和本轮问题交给通用多模态 Agent。
6. 返回一至两行可读摘要并使用 TTS 播报。
7. 本轮照片和音频只属于当前问答，不创建社交 `session_id`，不写入社交历史，不作为下一轮隐式上下文。

空白页必须和“无记录错误”区分：它是可用功能入口，不是故障状态。

## 3. 双屏职责与布局

实板映射已经冻结：物理右屏固定对应 `/dev/fb0`，物理左屏固定对应 `/dev/fb1`。文档中的
“左屏”和“右屏”均指佩戴者视角下的物理位置，不按 framebuffer 注册顺序推断。

### 3.1 启动与屏幕所有权

- `ai_agent` 产品配置不播放 `hello vela` 或其他板级开机动画。
- 板级代码只负责面板初始化、注册 `/dev/fb0`、`/dev/fb1` 和提交一次纯黑保护帧，不得在 VelaSight 启动前后绘制问候、idle 页面或其他业务信息。
- `board_early_initialize()` 必须在其他板级初始化前显式拉低 GPIO25，共享背光不得依赖复位默认电平；GC9D01 初始化和 `Display On` 命令期间继续保持关闭，避免未定义 GRAM 内容形成上电花屏。
- 两个 framebuffer 注册完成后，板级代码调用驱动已有的整帧填充接口，将两个 `160x160 RGB565` framebuffer 清为 `0x0000` 并各 push 一次；黑帧完成后启动 VelaSight，但共享背光继续保持关闭。
- 黑帧是 LVGL 接管前的显示保护，不是开机动画，不包含文字、Logo、进度或状态，也不得启动定时刷新。
- 黑帧处理完成后立即启动 `velasight` 任务，不等待 Camera、Audio、JPEG、Bluetooth、KVDB 或网络初始化完成，也不使用固定延时猜测 LVGL 是否就绪。
- VelaSight 打开两个 framebuffer、创建双屏组件树并写入“正在准备”快照后，必须显式 invalidate 两个根 screen，并分别同步执行一次 `lv_refr_now()`。NuttX backend 的 `FBIO_UPDATE` 和 GC9D01 整帧 push 均返回后，才调用板级 reveal 接口开启共享背光。
- reveal 只允许执行一次。背光开启后由 LVGL 持续拥有屏幕；其他板级状态模块不得覆盖 LVGL 页面。
- LVGL 第一帧使用产品背景和简洁的“正在准备”状态，它是首个业务画面；随后根据历史索引和网络加载结果进入历史页或可理解的错误页。
- 如果某块屏幕黑帧 push 失败，记录错误并继续启动 LVGL；不得因显示保护失败阻塞产品任务或其他数据路径。
- Camera、Audio、存储和网络继续在后台初始化；其结果通过 App 事件更新页面，不能夺回 framebuffer 或阻塞首帧。
- 非 VelaSight 诊断配置可以保留 `hello` 命令和底层动画函数用于屏幕测试，但不得在产品配置自动执行。

### 3.2 左屏 `/dev/fb1`：内容屏

左屏只显示用户需要阅读的内容：

- 历史记录标题、摘要、日期。
- 空白页拍照提示和问题提示。
- 社交辅助短建议和强烈情绪提醒。
- 社交结束后的摘要和建议。
- 闲时助手回答摘要。
- 网络配置中的 SSID 或错误原因。

左屏不显示索引、进度环、上传动画、技术字段和重复状态。

### 3.3 右屏 `/dev/fb0`：状态屏

右屏只显示设备当前状态：

- 当前模式。
- 历史序号和总记录数。
- 社交情绪和提醒状态。
- 录音、识别、思考、播报状态。
- 长按进度环。
- 暂停、完成、网络连接和错误状态。

右屏不显示长摘要、完整建议或历史正文。

### 3.4 双屏统一三层模板

两块屏幕均为 `160x160 px` 圆屏，使用完全一致的纵向分层。显示组件必须使用固定坐标，不得根据标题长度或页面内容动态移动分界线。

| 区域 | 纵向范围 | 推荐文本范围 | 左屏职责 | 右屏职责 |
| --- | --- | --- | --- | --- |
| 上层 | `y=8..28` | `x=48..112`，`64x20 px` | 内容类别或页面短标题 | 模式或状态类别 |
| 第一分界线 | `y=32` | 左右屏同轴 | 分隔标题和主内容 | 分隔标题和主状态 |
| 中层 | `y=35..106` | `x=12..148`，`136x71 px` | 摘要、建议、说明、配置内容 | 索引、核心状态、百分比、情绪 |
| 第二分界线 | `y=108` | 左右屏同轴 | 分隔主内容和底栏 | 分隔主状态和底栏 |
| 下层第一行 | `y=110..128` | 圆屏较宽弦区 | 日期、时间或较长元信息 | 返回键和下一条键提示 |
| 下层第二行 | `y=130..148` | `x=28..132`，`104x18 px` | 确认键的当前动作提示 | 不超过四字的短状态提示 |

两条分界线的具体要求：

- 第一分界线固定在 `y=32`，建议 `x=20`、宽 `120 px`、高 `1 px`。
- 第二分界线固定在 `y=108`，建议 `x=12`、宽 `136 px`、高 `1 px`。该位置在保证底部两行可见的前提下，尽量把圆屏中央的宽弦区域留给中层。
- 左右屏必须使用相同的 `y` 坐标和线条颜色；允许因圆屏弦宽不同而采用上述两种固定宽度，不允许逐页变化。
- 分界线使用低对比度蓝灰色，只表达信息结构，不得抢占主状态的视觉优先级。
- 长按进度环可以覆盖分界线，但不得引起标题、中层或底栏重新排版。

上层标题规则：

- 只允许一行，最多四个汉字；英文、数字和混排文字也必须控制在约 `64 px` 内。
- 标题使用固定 `16 px` 字体、居中和裁切模式，禁止自动换行、跑马灯和动态缩放。
- 业务层必须先改写语义，不依赖显示层截断。例如“正在整理交流记录”改为“整理记录”，“注意情绪变化”改为“情绪提醒”。
- 历史记录标题也必须在写入或生成时满足四字限制；完整标题需要保留时，应放入中层正文或详情数据，不能挤占上层。

推荐的现有页面标题映射：

| 原字段 | 上层短标题 |
| --- | --- |
| 正在准备 | 正在准备 |
| 拍照提问 | 拍照提问 |
| 进入社交辅助 | 进入社交 |
| 正在开始社交辅助 | 启动社交 |
| 社交辅助中 | 社交中 |
| 注意情绪变化 | 情绪提醒 |
| 结束本次交流 | 结束交流 |
| 正在整理交流记录 | 整理记录 |
| 本次交流摘要 | 交流摘要 |
| 可以这样做 | 回答建议 |
| 正在切换网络 | 切换网络 |
| 连接设备热点 | 设备热点 |

中层规则：

- 中层获得扣除上层和下层后的全部主要显示空间，所有摘要、提示、建议、索引和核心状态优先放在此处。
- 左屏中层允许自然换行，正文通常为一至三行；不得通过增加标题高度或侵入下层来容纳更多文字。
- 右屏中层短字段可放大，但必须使用独立的受约束对象：基础框为 `x=28..132`、`y=52..84`，按 `1.5x` 放大后的视觉边界为 `x=2..158`、`y=44..92`，不得越过 `y=32` 上层分界线或 `y=108` 下层分界线。
- 右屏超过四个汉字或约 `12` 个 UTF-8 字节的字段不得放大，使用 `x=16..144`、`y=43..104` 的普通 `16 px` 中层框自然换行；长 SSID 等内容不得移到底部短状态行。
- 左屏不得重复右屏索引或状态，右屏不得重复左屏长摘要。

### 3.5 底部双行栏

两块圆屏下层共同构成双行底栏。由于越靠近圆屏底部可用弦宽越窄，上行优先承载日期、时间和返回/下一条等需要横向空间的字段，下行承载居中的确认动作和短状态。三个按键位置固定对应物理按键：

```text
返回/取消        确认/当前动作        下一条
```

只显示当前页面有效的按键名称，无效位置留空。软键名称必须使用用户动作词，不使用 `POWER`、`BACK`、`NEXT`、`WAIT` 等技术或硬件词。左屏下行承载确认动作，右屏上行承载返回和下一条动作。

推荐词汇：

| 语义 | 软键文字 |
| --- | --- |
| 返回 | 返回 |
| 取消 | 取消 |
| 确认 | 确认 |
| 开始问答 | 询问 |
| 拍照入口 | 拍照提问 |
| 下一条记录 | 下一条 |
| 暂停 | 暂停 |
| 继续 | 继续 |
| 结束社交 | 结束 |
| 停止播报 | 停止 |
| 重试 | 重试 |

下层固定占用 `y=110..148`，正文不得压入该安全区。按键名称在两屏之间不得重复占位；左屏显示确认动作，右屏显示返回和下一条，具体分配由物理按键位置配置冻结。

底部两行对齐要求：

- 左屏日期、时间或较长上下文固定在 `y=110..128`，与右屏返回/下一条提示纵向对齐。时间不得放在更窄的最下行。
- 左屏确认动作固定在 `y=130..148`，与右屏短状态纵向对齐。
- 右屏返回/下一条固定在 `y=110..128`，右屏短状态固定在 `y=130..148`。
- 右屏第二行只显示短状态，原则上不超过四个汉字，例如“已保存”“准备好”“录音中”“处理中”“待连接”。
- 右屏不得把短状态放在按键提示上方；正确顺序始终是按键提示在上，短状态在最下方。
- 左屏没有日期或上下文时，上行留空，但仍保留该行空间，不得让中层或确认动作上移。
- 长按期间隐藏两屏全部按键提示；右屏下行可显示“按住中”“切换中”等短状态，层级坐标保持不变。

## 4. 按键反馈规则

### 4.1 单击

短按识别后，当前软键名称显示响应态：

- 软键文字短暂高亮或显示反色底。
- 响应态建议保持 100 至 150 ms，随后切换页面或进入下一阶段。
- 若动作立即切页，目标页面直接显示新状态，不叠加旧页面动画。
- 无效按键不显示误导性的响应态。

示例：

```text
历史页按“询问” -> 软键“询问”高亮 -> 进入“请说话”
空白页按“拍照提问” -> 软键高亮 -> 显示“正在拍照”
社交中按“暂停” -> 软键高亮 -> 两屏切换到“已暂停”
```

### 4.2 长按

长按用于防误触的开始、结束和网络模式切换。长按识别进入进度阶段后：

- 隐藏全部底部软键名称。
- 右屏只显示贴近屏幕外环的确定性进度环和中央百分比或目标状态。
- 左屏上层显示“进入社交”或“结束交流”，中层显示“继续按住”等目标说明。
- 提前松开显示短暂“已取消”，随后恢复原页面。
- 达到 100% 后显示动作结果，例如“已开始”“已结束”“正在切换”。

短按等待释放期间可以显示软键按下反馈；一旦进入长按进度阶段，不再显示软键名称。

### 4.3 错误页不使用长按

错误页只提供短按操作：

- 确认短按：重试。
- 返回短按：返回历史页或安全上一页。
- 下一条短按：仅在有多条错误详情时显示。
- 任意长按：无业务动作，不显示进度环，也不进入“长按失败界面”。

错误页不得设计“长按返回”“长按失败返回”“长按清除错误”等路径。

## 5. 页面与操作定义

### 5.1 历史记录页

左屏：

```text
上午交流

整体较平稳，
后段略有疑惑

08/18 09:20
```

右屏：

```text
历史

01/03

已保存
```

其中“已保存”固定在右屏最下方第二行；“返回”和“下一条”固定在其上方第一行。左屏较长的日期和时间放在上行，与右屏“返回/下一条”纵向对齐；左屏“询问”放在最下行，与右屏“已保存”纵向对齐。

软键：

```text
返回             询问              下一条
```

操作：

- 确认短按：启动针对当前记录的闲时语音助手。
- 确认长按：进入社交辅助长按进度。
- 下一条短按：切换下一条历史记录；最后一条之后进入空白页。
- 返回短按：保持历史页，不显示无意义的错误反馈。
- 返回与下一条组合长按：请求 STA/SoftAP 模式切换；进入组合进度后隐藏软键栏。

历史记录数量只统计有效历史记录，不包含空白页。当前索引在右屏显示为 `01/03`，进入空白页后显示 `拍照` 或 `--/03`，不得伪装成第四条记录。

### 5.2 历史记录空白页

空白页是历史浏览的固定末页，提供单张照片多模态 AI 交互。

左屏：

```text
拍照提问

拍一张照片，
然后直接问我
```

右屏：

```text
AI

照片问答

准备好
```

软键：

```text
返回            拍照提问
```

操作：

- 确认短按：进入“正在拍照”，拍摄一张可信 JPEG，随后进入语音聆听。
- 下一条短按：循环回到第一条历史记录；空白页不再进入第二张空白页。
- 返回短按：回到最新或上一次选中的历史记录。
- 确认长按：进入社交辅助长按进度；短按仍只触发本页单张照片问答。

拍照失败、录音失败或模型失败时进入统一错误页，不能回退为发送旧照片或旧历史记录。

### 5.3 社交辅助进入

左屏：

```text
进入社交

继续按住，松开取消
```

右屏：

```text
社交

0%
```

底部软键隐藏，右屏外环从 0% 填充到 100%。达到 100% 后生成 `session_id`，握手成功才进入社交中；失败进入错误页。

### 5.4 社交辅助运行

正常状态左屏：

```text
社交中

继续交流
```

右屏：

```text
社交中

观察中
```

软键：

```text
                 暂停
```

确认短按暂停/继续采集。暂停时左屏显示“已暂停，准备好后继续”，右屏显示“暂停”，确认软键改为“继续”。

无强烈情绪变化时不持续刷新普通情绪，也不播放提示音或 TTS。

### 5.5 社交强烈情绪提醒

左屏：

```text
情绪提醒

放慢语速，
先听对方说完
```

右屏：

```text
情绪升高

提醒
```

使用受控情绪颜色和短暂强调环，但始终保留文字。提醒不使用闪烁，不在交谈中途播放 TTS。增强建议晚到时只更新左屏内容，不阻塞图像和音频采集。

### 5.6 社交结束和最终结果

返回键长按进入结束进度：

左屏显示：

```text
结束交流

继续按住
```

右屏只显示退出进度环。达到 100% 后停止采集、上传尾包并请求最终结果。

处理阶段左屏依次显示：

```text
整理记录
正在生成建议
正在保存记录
```

右屏显示阶段状态，不显示技术协议。

成功后左屏显示摘要，右屏显示“已保存”和新记录索引。最终 TTS 播报期间，确认键短按停止播报，返回键短按取消并回到历史页。

### 5.7 闲时语音助手

历史记录问答：

左屏依次显示：

```text
请说话
说完自动结束
```

```text
正在理解
请稍等
```

```text
正在思考
很快回答你
```

右屏依次显示“聆听”“识别”“思考”“播报”。录音阶段右屏使用低频音量点或短弧反馈，不显示精确分贝。

空白页问答只在开始阶段增加：

```text
正在拍照
请看向目标
```

拍照成功后沿用同一套语音聆听、思考和播报页面。空白页照片不会写入历史。

语音回答左屏只显示一至两行 `display_text`，完整回答通过 TTS 播报。返回短按在录音、识别、思考和播报阶段均取消当前请求；取消后不得接受迟到回答。

### 5.8 SoftAP 和网络切换

历史页返回与下一条组合长按显示网络切换进度，软键栏隐藏。SoftAP 页面右屏 `/dev/fb0` 显示热点名称，左屏 `/dev/fb1` 显示密码、网页地址和连接状态。SoftAP 返回 STA 使用返回键长按进度，非错误页提前释放保持当前模式。

网络切换失败进入错误页，只能短按重试或返回，不能长按退出。

## 6. 显示组件规则

- 长按进度环尺寸约 `152x152`，贴近圆屏外环，外缘保留 2 至 3 px。
- 上层、中层、下层使用固定坐标；左右屏分界线固定为 `y=32` 和 `y=108`。
- 中层主内容安全区为 `x=12..148`、`y=35..106`；下层固定使用两行，不能被正文占用。
- 主状态、索引和情绪名称使用最大可用字号；动态中文摘要使用 16 px 完整 CJK 字体。
- 进度环只表达真实确定进度；等待云端使用低频分段状态，不伪造百分比。
- 情绪颜色只做第二通道，必须同时有情绪文字或行动建议。
- 静态页面只在快照变化时刷新；音量动画不高于 10 Hz，等待动画不高于 4 Hz。
- 任何页面不得在两屏显示同一条核心内容。
- 上层标题不得超过四个汉字；右屏最下方短状态不得超过四个汉字。

## 7. 状态与软键快照

显示层使用不可变快照，不直接读取业务状态。快照至少包含：

- 页面状态和内容屏文本。
- 状态屏模式、状态、索引和完成状态。
- 软键三个位置的显示文字、是否有效和响应高亮状态。
- 长按进度是否显示、进度值和目标动作。
- 情绪枚举、颜色和提醒文本。
- 空白页标志和照片问答阶段。
- 错误类别、可重试标志和短按动作。

建议增加以下页面状态：

```text
VS_PAGE_HISTORY
VS_PAGE_HISTORY_BLANK
VS_PAGE_SOCIAL_ENTER
VS_PAGE_SOCIAL_RUNNING
VS_PAGE_SOCIAL_ALERT
VS_PAGE_SOCIAL_PAUSED
VS_PAGE_SOCIAL_EXITING
VS_PAGE_SOCIAL_FINALIZING
VS_PAGE_VOICE_LISTENING
VS_PAGE_VOICE_THINKING
VS_PAGE_VOICE_SPEAKING
VS_PAGE_NET_SWITCHING
VS_PAGE_SOFTAP
VS_PAGE_ERROR
```

照片问答可以复用语音阶段状态，但必须由快照携带 `photo_context=true`，确保拍照和历史问答的提示语不同。

## 8. 实现改造边界

### 8.1 `vs_types.h`

增加空白页标志、照片问答上下文、软键描述、软键响应态、长按进度类型和内容/状态双屏字段。空白页不得复用 `history_count`，应通过独立的 `history_is_blank` 表达。

### 8.2 `vs_app.c`

- 历史索引在最后一条记录之后进入空白页，再循环到第一条记录。
- 空白页确认短按启动单张拍照多模态问答。
- 历史记录确认短按只启动当前记录问答。
- 社交辅助仍由历史记录页确认长按进入。
- 社交中确认短按暂停/继续，返回长按结束。
- 删除错误页长按相关分支和 `error_back_progress`。
- 每次短按动作设置对应软键响应态，页面切换后清除旧响应。

### 8.3 `vs_display.c`

- 物理左侧内容屏 `/dev/fb1` 和物理右侧状态屏 `/dev/fb0` 使用独立组件树。
- 两棵组件树复用相同的三层坐标常量，两条分界线在 `y=32` 和 `y=108` 对齐。
- 进度环只在长按阶段或实际等待阶段显示；错误页强制隐藏。
- 下层固定为双行：左屏 `y=110..128` 显示时间或元信息、`y=130..148` 显示确认动作；右屏 `y=110..128` 显示返回/下一条、`y=130..148` 显示短状态。长按阶段隐藏按键字段。
- 右屏短核心字段只允许在受约束的中层框内放大；禁止对整个中层标签做会跨越分界线的几何变换。
- 历史记录页和空白页使用不同内容模板。
- 右屏负责索引、模式、情绪和动画，左屏负责摘要、建议和操作说明。

### 8.4 板级显示启动

- `bk7258_bringup.c` 在 VelaSight 产品配置下跳过 `bk7258_gc9d01_fb_hello_animate()` 和板级 idle 状态绘制。
- `/dev/fb0`、`/dev/fb1` 注册完成后立即调用 `velasight_autostart()`，后续外设初始化不得覆盖屏幕。
- `hello` 绘图函数和命令只作为非产品配置下的诊断能力保留。

### 8.5 `vs_input.c`

保留短按、长按和组合长按的业务事件；如需按下高亮，增加不触发业务的按键按下/释放反馈事件。长按进度只对有效页面显示，错误页收到进度事件时必须被业务层丢弃。

## 9. 验收矩阵

| 场景 | 验收标准 |
| --- | --- |
| 历史浏览 | 三条记录后必定出现一张空白页；空白页不计入记录总数 |
| 空白页拍照 | 只拍一张可信 JPEG；失败不使用旧照片、不写历史 |
| 空白页问答 | 问题和单张照片进入通用多模态 Agent；回答可显示和 TTS 播放 |
| 历史问答 | 只携带当前选中记录；不携带其他记录 |
| 社交开始 | 历史页确认长按显示外环进度；成功后创建会话并开始采集 |
| 社交运行 | 图片和音频职责正确；普通情绪静默；强烈情绪显示文字和颜色 |
| 社交结束 | 返回长按显示进度；最终结果包含字幕、情绪、摘要、建议并保存 |
| 软键栏 | 每页只显示有效按键名称；短按有响应态；长按阶段名称隐藏 |
| 三层布局 | 双屏分界线均为 `y=32`、`y=108`；所有页面切换时位置不跳动 |
| 上层标题 | 单行显示，现有字段均不超过四个汉字，无换行和裁切 |
| 下层双行 | 左屏时间与右屏返回/下一条在 `y=110..128`；左屏确认动作与右屏短状态在 `y=130..148` |
| 中层边界 | 右屏短字段放大后仍处于 `y=44..92`，长字段处于 `y=43..104`，均不侵占上下层 |
| 错误页 | 只有短按重试/返回；没有长按进度和长按失败界面 |
| 双屏职责 | 左屏无索引动画，右屏无长摘要；不重复显示核心内容 |
| 开机接管 | 面板初始化时背光关闭；双 framebuffer 注册后各 push 一帧纯黑；LVGL 双屏首帧同步 push 完成后才开背光；无花屏和旧问候动画；后续板级初始化不覆盖 |
| 取消 | 取消后释放照片、音频、网络和 TTS 资源；迟到结果不得污染下一轮 |

## 10. 实施顺序

1. 取消产品配置的板级开机动画；面板初始化保持背光关闭，双 framebuffer 注册后提交双屏纯黑保护帧并启动 VelaSight；LVGL 同步提交双屏首帧后再开背光。
2. 保持已冻结的屏幕映射：物理右屏为 `/dev/fb0`，物理左屏为 `/dev/fb1`；再冻结物理按键到软键栏的位置映射。
3. 扩展 UI 快照和页面枚举，加入空白页和照片问答上下文。
4. 重构双屏显示模板和底部软键栏。
5. 实现历史记录到空白页的循环浏览和空白页短按拍照入口。
6. 接入单张照片问答的 `voice-vision/v1` 或本地 `ai_agent` 多模态入口。
7. 实现短按响应态、长按隐藏软键和外环进度。
8. 删除错误页全部长按路径，补充短按重试/返回。
9. 依次完成历史问答、社交辅助、最终结果和实板验收。
