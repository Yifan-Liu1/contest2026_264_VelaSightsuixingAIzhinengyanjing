# BK7258 VelaSight 最终固件构建步骤

本文记录 VelaSight 产品固件的构建流程。这里必须区分两个 OpenVela
配置：`nsh` 是最小 NSH bring-up 和容量对照配置，只用于底层启动、串口和
资源基线验证；`ai_agent` 是当前 VelaSight 产品配置，包含双屏 VelaSight
App、LVGL framebuffer backend、Arc、Label 和 UTF-8 中文显示所需配置。

早期文档使用 `nsh` 是因为 AP 启动和基础外设验证先以最小配置完成。随着
VelaSight App 和 LVGL 接入，继续使用 `nsh` 会生成一个不含产品界面的合法
基线镜像，导致打包成功但设备没有目标 UI。最终烧录必须使用 `ai_agent`。

最终固件由以下三部分组成：

```text
OpenVela CPU1/AP nuttx.bin
Armino CPU0/CP app.bin
Beken bootloader.bin
        |
        v
Beken packager
        |
        v
all-app.bin
```

OpenVela 只构建 AP raw binary。CP、bootloader、分区生成和最终打包均由
`bk_avdk_smp/projects/app_ab` 完成。不要手工覆盖打包目录中的 `app1.bin`，
应使用已经接入的 `EXTERNAL_AP_BIN` 接口。

## 1. 前置条件

工作区路径：

```text
/home/mi/vela_competition/contest
/home/mi/vela_competition/bk_avdk_smp
```

先阅读 [`external/README.md`](../external/README.md)。比赛仓的 `external/apps`、
`external/nuttx`、`external/packages/ai_agent` 和 `external/bk_avdk_smp` 按目标仓
相对路径保存完整最终文件；`external/manifest.tsv` 固定四个目标仓基线、Armino
镜像 ID 和离线归档 SHA-256。需要显式准备或只读验证时，从比赛仓根执行：

```bash
cd /home/mi/vela_competition/contest/contest2026_264_VelaSightsuixingAIzhinengyanjing
./external/prepare.sh install
./external/prepare.sh check
```

`install` 全量预检后才安装，`check` 不修改任何目标仓文件。产品构建推荐直接使用
`./build_and_flash.sh --prepare-overlay`，它会安装后构建；不带
`--prepare-overlay` 时只执行 `check`。

Armino 1.5 官方镜像可从 [Docker Hub](https://hub.docker.com/r/bekencorp/armino-idk/tags)
拉取，或从 [Beken 下载站](https://dl.bekencorp.com/tools/arminosdk/docker_img/armino-idk)
取得离线归档。不要仅凭 tag 判断镜像：当前测试镜像 ID 与离线包 SHA-256 均以
`external/manifest.tsv` 为准，`build_and_flash.sh` 会拒绝镜像 ID 不匹配的构建。
确认本地存在 manifest 指定的 `localhost/bekencorp/armino-idk:1.5`：

```bash
podman images
```

`app_ab` 使用 overlay 管理的分区配置：

```text
bk_avdk_smp/projects/app_ab/partitions/bk7258/auto_partitions.csv
bk_avdk_smp/projects/app_ab/partitions/bk7258/ram_regions.csv
```

不得混用 `bk_solution_ai` 等其他项目的分区文件，也不要手工同步这些源文件或恢复
生成后的 CP config。统一脚本会通过 `EXTERNAL_AP_BIN` 打包，并在成功或失败退出时恢复
最小 CP config；成功路径在恢复后再次执行只读 overlay 检查，失败路径保留原错误状态。

## 2. 高级：构建 OpenVela AP（VelaSight 使用 ai_agent）

以下第 2～6 节保留为底层展开步骤和故障诊断参考，不是产品推荐入口。开始任何手工
高级构建前，必须先从比赛仓根完成只读 overlay 检查：

```bash
cd /home/mi/vela_competition/contest/contest2026_264_VelaSightsuixingAIzhinengyanjing
./external/prepare.sh check
```

然后回到 OpenVela 根构建 AP：

```bash
cd /home/mi/vela_competition/contest

./build.sh \
  vendor/beken/boards/bk7258/bk7258-ap/configs/ai_agent \
  --cmake \
  -j8
```

如修改过 `Kconfig` 或 `defconfig`，建议先删除旧 CMake 配置：

```bash
./build.sh \
  vendor/beken/boards/bk7258/bk7258-ap/configs/ai_agent \
  --cmake distclean
```

实际输出：

```text
contest/cmake_out/bk7258-ap_ai_agent/nuttx       # ELF
contest/cmake_out/bk7258-ap_ai_agent/nuttx.bin   # AP raw binary
contest/cmake_out/bk7258-ap_ai_agent/System.map
```

检查 AP 文件：

```bash
stat -c '%s %y %n' cmake_out/bk7258-ap_ai_agent/nuttx.bin
sha256sum cmake_out/bk7258-ap_ai_agent/nuttx.bin
```

AP 必须使用 Cortex-M33 hard-float 配置，链接地址必须与 `app_ab` 的 AP
布局匹配，并且 `nuttx.bin` 不得超过 AP 分区容量。当前 `primary_ap_app`
已按 Beken 的 `34K` code 分区对齐规则扩展为 `4148K`，这是固定数据分区
之前的最大合法值；对应 AP raw linker 区域为 `3904K`（`0x3d0000`），由
`board/beken/boards/bk7258/bk7258-ap/scripts/ld.script` 同步定义。

## 4. 构建 CP 并打包最终固件

在 `bk_avdk_smp` 根目录执行：

```bash
cd /home/mi/vela_competition/bk_avdk_smp

podman run --rm \
  --userns=keep-id \
  -v "$PWD:/armino" \
  -w /armino \
  localhost/bekencorp/armino-idk:1.5 \
  make -C projects/app_ab bk7258 \
  SDK_DIR=/armino \
  EXTERNAL_AP_BIN=/armino/build/openvela-ap.bin
```

该命令自动完成：

1. 生成 `app_ab` 分区文件。
2. 构建 Armino CPU0/CP。
3. 获取 Beken bootloader。
4. 将 `EXTERNAL_AP_BIN` 复制为打包输入 `app1.bin`。
5. 调用标准 Beken packager 生成最终固件。

仅安装 Podman 时不要使用会在内部调用 Docker 的 `dbuild.sh`。

## 6. 构建后校验

首先确认最终文件存在：

```bash
ls -lh \
  projects/app_ab/build/bk7258/app_ab/package/all-app.bin \
  projects/app_ab/build/bk7258/app_ab/package/app_ab_crc.rbl
```

然后确认 packager 使用了本次构建的 OpenVela AP：

```bash
sha256sum \
  /home/mi/vela_competition/contest/cmake_out/bk7258-ap_ai_agent/nuttx.bin \
  build/openvela-ap.bin \
  projects/app_ab/build/bk7258/app_ab/package/tmp/app1.bin

cmp -s \
  /home/mi/vela_competition/contest/cmake_out/bk7258-ap_ai_agent/nuttx.bin \
  projects/app_ab/build/bk7258/app_ab/package/tmp/app1.bin
```

三个 SHA256 必须一致，`cmp` 必须返回 0。否则生成的 `all-app.bin` 可能仍包含旧 AP。

检查分区和构建摘要：

```bash
cat projects/app_ab/build/bk7258/app_ab/partitions/bk_package.json
cat projects/app_ab/build/bk7258/app_ab/package/build_summary.txt
```

`bk_package.json` 应包含：

```text
bootloader.bin -> bootloader
app.bin        -> CPU0/CP app
app1.bin       -> CPU1/AP app
```

注意：`build_summary.txt` 中的 AP memory info 来自构建过程中的 Armino AP
占位镜像 map，不用于证明外部 OpenVela AP 已经打包。外部 AP 是否生效必须以
`nuttx.bin`、`build/openvela-ap.bin` 和 `package/tmp/app1.bin` 的哈希及
逐字节比较为准。

## 8. 一键构建、打包和烧录

产品构建使用仓库内的自动化入口。它固定选择 `ai_agent`，先安装完整文件 overlay，
执行 OpenVela clean build、AP/CP clean build、分区生成、外部 AP 注入、三份 AP
二进制比较，并可通过 `--flash` 使用 shell 串口软重启烧录和采集完整启动日志：

```bash
cd /home/mi/vela_competition/contest/contest2026_264_VelaSightsuixingAIzhinengyanjing
./build_and_flash.sh --prepare-overlay
./build_and_flash.sh --prepare-overlay --flash -p /dev/ttyUSB0 -n 0
```

不带 `--prepare-overlay` 时只执行只读 overlay `check`，不会安装文件。脚本会按
`external/manifest.tsv` 校验 Armino 镜像 ID，并在 Armino 构建成功或失败时恢复最小
CP config；成功路径恢复后再次执行 `external/prepare.sh check`，失败路径恢复后保留原退出状态。

串口日志使用 `stty`、`tee`、`timeout` 和脚本内的软重启序列，不使用 Python。
`ps` 是当前 CP shell 的已知崩溃命令，不纳入启动门禁；启动门禁观察 CP/AP
握手、双屏 framebuffer、背光关闭期间的双屏纯黑保护帧、LVGL 双屏首帧完成后的
`backlight on` 握手、`velaclaw` client 和无 heartbeat timeout；产品配置不得出现上电花屏、旧的板级开机
问候动画或 idle 页面。

- OpenVela CMake 构建产物是 `nuttx.bin` 和 `System.map`，不是
  `vela_nuttx.bin` 或 `nuttx.map`。
- `nsh` 与 `ai_agent` 是两个不同的板级配置。`nsh` 只能作为最小启动和
  对照基线；VelaSight 的 LVGL、中英文界面和 `ai_agent` 必须从
  `configs/ai_agent` 构建。
- 标准产品构建不强制 `-Werror`；完整 `packages_ai_agent` overlay 已修复已知告警，
  `configs/ai_agent` 另行使用 `-e -Werror` 验证通过。`nsh` 的 warning 策略不能替代产品配置验证。
- 当前 OpenVela 工作树是 `/home/mi/vela_competition/contest`，不是旧的
  `openvela_bk7258_dev`。
- `EXTERNAL_AP_BIN` 必须填写容器内路径
  `/armino/build/openvela-ap.bin`，不能填写宿主机绝对路径。
- 修改配置后若增量构建没有加载新配置，先执行 CMake `distclean`。
- 最终烧录文件名是 `all-app.bin`，不是 `all_app.bin`。
- 当前 AP 分区为合法对齐值 `4148K`，对应完整 CJK 字库构建的
  `all-app.bin` 大小为 `5709824` 字节；自动烧录脚本会在烧前校验该值。若再次调整分区，必须
  同步更新校验值，不能使用旧的 `2646016` 字节基线。
