# BK7258 最终固件构建步骤

本文记录当前工作区已经验证通过的构建流程。最终固件由以下三部分组成：

```text
OpenVela CPU1/AP nuttx.bin
Armino CPU0/CP app.bin
Beken bootloader.bin
        |
        v
Beken packager
        |
        v
all-app.bin
```

OpenVela 只构建 AP raw binary。CP、bootloader、分区生成和最终打包均由
`bk_avdk_smp/projects/app_ab` 完成。不要手工覆盖打包目录中的 `app1.bin`，
应使用已经接入的 `EXTERNAL_AP_BIN` 接口。

## 1. 前置条件

工作区路径：

```text
/home/mi/vela_competition/contest
/home/mi/vela_competition/bk_avdk_smp
```

确认官方 Armino 1.5 Podman 镜像存在：

```bash
podman images
```

应包含：

```text
localhost/bekencorp/armino-idk:1.5
```

`app_ab` 使用自己的分区配置：

```text
bk_avdk_smp/projects/app_ab/partitions/bk7258/auto_partitions.csv
bk_avdk_smp/projects/app_ab/partitions/bk7258/ram_regions.csv
```

不得混用 `bk_solution_ai` 等其他项目的分区文件。

## 2. 构建 OpenVela AP

```bash
cd /home/mi/vela_competition/contest

./build.sh \
  vendor/beken/boards/bk7258/bk7258-ap/configs/nsh \
  -e -Werror \
  --cmake \
  -j8
```

如修改过 `Kconfig` 或 `defconfig`，建议先删除旧 CMake 配置：

```bash
./build.sh \
  vendor/beken/boards/bk7258/bk7258-ap/configs/nsh \
  --cmake distclean
```

实际输出：

```text
contest/cmake_out/bk7258-ap_nsh/nuttx       # ELF
contest/cmake_out/bk7258-ap_nsh/nuttx.bin   # AP raw binary
contest/cmake_out/bk7258-ap_nsh/System.map
```

检查 AP 文件：

```bash
stat -c '%s %y %n' cmake_out/bk7258-ap_nsh/nuttx.bin
sha256sum cmake_out/bk7258-ap_nsh/nuttx.bin
```

AP 必须使用 Cortex-M33 hard-float 配置，链接地址必须与 `app_ab` 的 AP
布局匹配，并且 `nuttx.bin` 不得超过 AP 分区容量。

## 3. 准备外部 AP 输入

Podman 只挂载 `bk_avdk_smp`，因此先把 AP raw binary 复制到 SDK 内部：

```bash
cp \
  /home/mi/vela_competition/contest/cmake_out/bk7258-ap_nsh/nuttx.bin \
  /home/mi/vela_competition/bk_avdk_smp/build/openvela-ap.bin
```

确认源文件和复制结果一致：

```bash
sha256sum \
  /home/mi/vela_competition/contest/cmake_out/bk7258-ap_nsh/nuttx.bin \
  /home/mi/vela_competition/bk_avdk_smp/build/openvela-ap.bin
```

## 4. 构建 CP 并打包最终固件

在 `bk_avdk_smp` 根目录执行：

```bash
cd /home/mi/vela_competition/bk_avdk_smp

podman run --rm \
  --userns=keep-id \
  -v "$PWD:/armino" \
  -w /armino \
  localhost/bekencorp/armino-idk:1.5 \
  make -C projects/app_ab bk7258 \
  SDK_DIR=/armino \
  EXTERNAL_AP_BIN=/armino/build/openvela-ap.bin
```

该命令自动完成：

1. 生成 `app_ab` 分区文件。
2. 构建 Armino CPU0/CP。
3. 获取 Beken bootloader。
4. 将 `EXTERNAL_AP_BIN` 复制为打包输入 `app1.bin`。
5. 调用标准 Beken packager 生成最终固件。

仅安装 Podman 时不要使用会在内部调用 Docker 的 `dbuild.sh`。

## 5. 输出文件

完整烧录固件：

```text
/home/mi/vela_competition/bk_avdk_smp/projects/app_ab/build/bk7258/app_ab/package/all-app.bin
```

OTA 固件：

```text

```

最终打包输入：

```text
package/tmp/bootloader.bin  # Beken bootloader
package/tmp/app.bin         # Armino CPU0/CP
package/tmp/app1.bin        # OpenVela CPU1/AP
```

实际完整路径的共同前缀为：

```text
/home/mi/vela_competition/bk_avdk_smp/projects/app_ab/build/bk7258/app_ab/
```

## 6. 构建后校验

首先确认最终文件存在：

```bash
ls -lh \
  projects/app_ab/build/bk7258/app_ab/package/all-app.bin \
  projects/app_ab/build/bk7258/app_ab/package/app_ab_crc.rbl
```

然后确认 packager 使用了本次构建的 OpenVela AP：

```bash
sha256sum \
  /home/mi/vela_competition/contest/cmake_out/bk7258-ap_nsh/nuttx.bin \
  build/openvela-ap.bin \
  projects/app_ab/build/bk7258/app_ab/package/tmp/app1.bin

cmp -s \
  /home/mi/vela_competition/contest/cmake_out/bk7258-ap_nsh/nuttx.bin \
  projects/app_ab/build/bk7258/app_ab/package/tmp/app1.bin
```

三个 SHA256 必须一致，`cmp` 必须返回 0。否则生成的 `all-app.bin` 可能仍包含旧 AP。

检查分区和构建摘要：

```bash
cat projects/app_ab/build/bk7258/app_ab/partitions/bk_package.json
cat projects/app_ab/build/bk7258/app_ab/package/build_summary.txt
```

`bk_package.json` 应包含：

```text
bootloader.bin -> bootloader
app.bin        -> CPU0/CP app
app1.bin       -> CPU1/AP app
```

注意：`build_summary.txt` 中的 AP memory info 来自构建过程中的 Armino AP
占位镜像 map，不用于证明外部 OpenVela AP 已经打包。外部 AP 是否生效必须以
`nuttx.bin`、`build/openvela-ap.bin` 和 `package/tmp/app1.bin` 的哈希及
逐字节比较为准。

## 7. 常见问题

- OpenVela CMake 构建产物是 `nuttx.bin` 和 `System.map`，不是
  `vela_nuttx.bin` 或 `nuttx.map`。
- 当前 OpenVela 工作树是 `/home/mi/vela_competition/contest`，不是旧的
  `openvela_bk7258_dev`。
- `EXTERNAL_AP_BIN` 必须填写容器内路径
  `/armino/build/openvela-ap.bin`，不能填写宿主机绝对路径。
- 修改配置后若增量构建没有加载新配置，先执行 CMake `distclean`。
- 最终烧录文件名是 `all-app.bin`，不是 `all_app.bin`。
